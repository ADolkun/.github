# Contributing

Thanks for helping. This guide applies to every repository under [ADolkun](https://github.com/ADolkun) that has no contributing guide of its own.

## Issues

- Search the existing issues first.
- **Bugs:** use the bug report form. Say what you ran, what you expected and what happened, with versions and the smallest example that shows it.
- **Ideas:** use the feature request form. Describe the problem before the solution.
- **Security problems:** don't open an issue. Follow the [security policy](https://github.com/ADolkun/.github/blob/main/SECURITY.md).

## Pull requests

1. For anything bigger than a small fix, open an issue first, so we agree on the approach before you put time in.
2. Fork the repository and branch from its default branch.
3. Set up and run the checks the repository's README describes. CI runs them on every pull request, and they must pass before a merge.
4. Keep each pull request to one change. Add or update tests for behaviour you change, and update the docs that describe it.
5. Title it as a [Conventional Commit](https://www.conventionalcommits.org/), such as `fix: …`, `feat: …` or `docs: …`. Pull requests are usually squash-merged, so the title becomes the commit message.
6. Fill in the pull request template.

The maintainer reviews pull requests as time allows. A quiet pull request isn't a rejected one.
